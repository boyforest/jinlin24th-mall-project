# 金霖二十四养管理端操作文档

适用对象：运营、仓库、客服、订单处理人员。  
覆盖范围：管理后台 `admin-web` 与 C 端小程序 `c-uniapp` 的商品、库存、订单主流程。

## 1. 登录与通用操作

1. 打开管理后台，使用管理员账号登录。
2. 左侧菜单按业务分组：
   - 首页：查看概览数据。
   - 商品：商品管理、规格管理、分类管理。
   - 交易：订单管理、优惠券、活动运营。
   - 仓储：仓库管理、库存管理、库存流水。
   - 增长：用户管理、分销管理、客户管理、跟进记录。
3. 列表页常用按钮：
   - 查询：按筛选条件搜索。
   - 重置：清空筛选条件。
   - 刷新：重新加载当前列表。
   - 新增：创建新记录。
   - 查看：查看详情。
   - 编辑：修改记录。
   - 删除：删除记录，删除前会二次确认。

## 2. 商品上线机制

商品要在小程序中正常售卖，需要同时满足以下条件：

1. 商品状态为“启用”。
2. 商品所属分类状态为“启用”。
3. 商品至少有一个“启用”的规格 SKU。
4. 对应 SKU 在“库存管理”中有可用库存。
5. 商品图片、名称、价格、详情等信息已填写完整。

### 2.1 分类管理

路径：商品 > 分类管理

用途：维护小程序首页左侧分类。

操作要点：

- 新增分类时填写分类名称、排序、状态。
- 状态为“启用”的分类会出现在小程序分类列表中。
- 排序数字越小，在小程序分类列表中越靠前。
- 如果分类被禁用，该分类不会展示，但分类下的商品数据仍保留。

### 2.2 商品管理

路径：商品 > 商品管理

用途：维护商品基础信息。

主要字段说明：

- 商品分类：选择商品所属分类。
- 商品名称：小程序列表和详情页展示的主标题。
- 副标题：小程序中展示的简短卖点。
- 主图：小程序列表和详情页首图。
- 图片列表：详情页轮播图，多张图片用英文逗号分隔。
- 详情：商品详情内容，支持富文本 HTML。
- 功效说明：详情页“功效说明”区域。
- 注意事项：详情页“注意事项”区域。
- 默认价格：创建商品时会自动生成一个名为“默认”的 SKU；后续修改默认价格，会同步更新“默认”SKU 的价格。
- 状态：启用表示上架，禁用表示下架。
- 排序：小程序商品列表按排序和 ID 展示，排序越大越靠前。

推荐操作流程：

1. 先确认分类已存在且启用。
2. 新增商品，先填写名称、分类、主图、详情、功效、注意事项。
3. 如果只卖一个规格，可填写默认价格，系统会自动创建“默认”规格。
4. 如果有多个规格，到“规格管理”继续补充。
5. 商品信息确认无误后，将商品状态改为“启用”。

### 2.3 规格管理

路径：商品 > 规格管理

用途：维护商品的规格、价格和小程序展示余量。

主要字段说明：

- 商品 ID：规格归属的商品 ID。
- 规格名称：例如 `500g/盒`、`礼盒装`。
- 售价：普通售价。
- 会员价：有会员价时，小程序优先展示和使用会员价。
- 库存：小程序首页、详情页、购物车展示的余量字段。
- 规格图片 URL：规格图片。
- 状态：启用表示该规格可在小程序选择；禁用后不在小程序规格列表展示。

重要说明：

- 小程序展示的“库存/余量”来自规格管理里的 `库存` 字段。
- 下单真正扣减的是“库存管理”里的仓库库存。
- 上线前请保持“规格库存”和“仓库库存”一致，避免用户看到有余量但提交订单提示库存不足。

### 2.4 小程序展示规则

C 端小程序会展示以下内容：

- 首页商品列表：只展示启用商品。
- 分类筛选：只展示启用分类。
- 商品详情：只允许打开启用商品。
- 规格选择：只展示启用 SKU。
- 默认选中规格：优先选择 `stock > 0` 的 SKU；如果都没有库存，页面可能默认带上第一个 SKU，最终仍以仓库库存校验为准。
- 加入购物车/立即购买：需要用户登录。

## 3. 库存机制

系统里有两类容易混淆的库存：

| 库存位置 | 用途 | 是否真正扣减 |
| --- | --- | --- |
| 规格管理 > 库存 | 给小程序展示余量，购物车也会读取 | 否 |
| 库存管理 > 当前库存 | 仓库真实可售库存，下单时扣减 | 是 |

### 3.1 仓库管理

路径：仓储 > 仓库管理

用途：维护发货仓库基础信息。

操作要点：

- 可新增、编辑、删除仓库。
- 仓库字段包括名称、地址、联系人、电话、状态。
- 当前下单扣库存时，会按 SKU 查找第一条有足够库存的仓库库存记录。
- 目前订单明细中没有保存仓库 ID，因此多仓发货时需在库存流水中核对实际扣减仓库。

### 3.2 库存管理

路径：仓储 > 库存管理

用途：维护“仓库 + SKU”的真实库存。

主要字段说明：

- 仓库：库存所属仓库。
- SKU：库存对应规格。
- 当前库存：真实可售库存，下单时扣减。
- 预警库存：当前库存小于或等于预警库存时，列表会用红色标识。

日常操作：

1. 按仓库或 SKU 搜索库存记录。
2. 点击编辑，修改当前库存或预警库存。
3. 补货时调高当前库存。
4. 盘点少货时调低当前库存。
5. 修改后到库存流水或订单链路中核对变化。

当前限制：

- 管理后台库存页当前只支持编辑已有库存记录，没有“新增库存”按钮。
- 一个仓库同一个 SKU 只能有一条库存记录。
- 如果新建了 SKU，但库存管理里没有对应记录，需要通过初始化数据或后端补录库存记录后，才能正常扣减库存。

### 3.3 库存流水

路径：仓储 > 库存流水

用途：查看库存变动记录。

流水类型：

- 入库：数量为正数，表示库存增加。
- 出库：数量为负数，表示库存减少。
- 盘点调整：用于盘点场景。

系统自动产生的流水：

- 用户提交订单成功后，系统立即占用库存，生成“出库”流水，备注为“用户下单占用库存”。
- 待付款订单被后台取消或超时自动取消后，系统恢复库存，生成“入库”流水。

## 4. 订单与库存联动

订单状态：

| 状态 | 含义 | 管理端可操作 |
| --- | --- | --- |
| 待付款 | 用户已提交订单，尚未支付 | 可取消，取消后恢复库存 |
| 待发货 | 用户已支付 | 可发货 |
| 待收货 | 已发货，等待用户收货 | 可完成 |
| 已完成 | 订单结束 | 查看 |
| 已取消 | 订单关闭 | 查看 |
| 退款中/已退款 | 退款流程状态 | 查看 |

库存扣减与恢复规则：

1. 用户提交订单时，系统会立即占用仓库库存。
2. 如果仓库库存不足，订单创建失败，用户无法提交成功。
3. 用户支付成功后，订单变为“待发货”，库存不再重复扣减。
4. 待付款订单被取消时，系统会恢复之前占用的库存。
5. 已支付订单后台不能直接取消；需要走退款/售后流程。

订单处理路径：交易 > 订单管理

常用操作：

- 待付款：点击“取消”，库存会恢复。
- 待发货：点击“发货”，订单变为待收货。
- 待收货：点击“完成”，订单变为已完成。
- 查看详情：核对收货人、电话、地址、推荐官、金额、时间等信息。

## 5. 商品上线标准流程

建议每个新品按以下顺序操作：

1. 分类准备：确认分类已创建并启用。
2. 商品录入：在商品管理新增商品，填写主图、标题、副标题、详情、功效、注意事项。
3. 规格录入：在规格管理创建或编辑 SKU，填写规格名、价格、会员价、规格库存、启用状态。
4. 仓库库存准备：在库存管理确认对应 SKU 有真实库存，并设置预警库存。
5. 状态确认：商品启用、SKU 启用、分类启用。
6. 小程序检查：首页能看到商品，分类能筛选到商品，详情页能看到规格和余量。
7. 下单测试：使用测试账号加入购物车、提交订单，确认库存会扣减并生成库存流水。
8. 取消测试：取消待付款订单，确认库存恢复并生成入库流水。

上线前检查表：

| 检查项 | 要求 |
| --- | --- |
| 分类 | 已启用 |
| 商品 | 已启用，名称/图片/详情完整 |
| SKU | 至少一个启用 SKU |
| SKU 展示库存 | 与实际仓库库存一致或不大于实际库存 |
| 仓库库存 | 对应 SKU 有库存记录，当前库存大于 0 |
| 预警库存 | 已设置合理阈值 |
| 小程序 | 首页、分类、详情均能正常展示 |
| 下单 | 可提交订单并扣减库存 |
| 取消 | 待付款订单取消后库存可恢复 |

## 6. C 端小程序用户流程

用户能看到和操作的主要流程：

1. 首页浏览商品，可按分类筛选或搜索关键词。
2. 点击商品进入详情页，查看轮播图、功效说明、注意事项、商品详情。
3. 选择启用规格；页面会展示规格余量，最终能否下单以仓库库存为准。
4. 加入购物车或立即购买。
5. 填写收货人、手机号、详细地址和备注。
6. 可确认或绑定推荐官。
7. 提交订单并调起微信支付。
8. 支付成功后订单进入待发货。
9. 后台发货后，用户在订单详情中确认收货。

## 7. 常见问题

### 商品后台启用了，小程序看不到

优先检查：

- 商品状态是否启用。
- 分类状态是否启用。
- 商品是否被删除。
- 小程序是否筛选了其他分类或关键词。
- 商品缓存可能存在短时间延迟，可刷新后再检查。

### 商品能看到，但规格不可买或下单失败

优先检查：

- 规格是否属于该商品 ID。
- 规格状态是否启用。
- 规格管理里的库存是否大于 0。
- 库存管理里的真实仓库库存是否足够。

### 小程序显示有库存，但下单提示库存不足

原因通常是规格管理里的展示库存有值，但库存管理里的真实仓库库存不足或没有库存记录。

处理方式：

1. 到规格管理确认该 SKU 的展示库存。
2. 到库存管理按 SKU 搜索真实库存。
3. 将库存管理里的当前库存补足。
4. 再次测试下单。

### 下单后库存什么时候扣

用户提交订单成功时立即扣减仓库库存，不是支付成功后才扣。

### 用户取消支付后库存会不会马上恢复

如果只是关闭微信支付弹窗，订单仍是待付款，库存仍处于占用状态。库存会在订单被后台取消或系统超时自动取消后恢复。

### 新建 SKU 后库存管理搜不到

当前后台没有新增库存按钮，新 SKU 需要先补录一条“仓库 + SKU”的库存记录。上线前务必检查这一项。

## 8. 上线调试建议

1. 每个正式商品至少做一次完整链路测试：展示、加购、下单、支付前取消、库存恢复。
2. 重点核对 SKU 展示库存与仓库库存是否一致。
3. 测试订单完成后，在库存流水中按 SKU 或订单号核对扣减记录。
4. 正式推广前，先禁用不售卖的测试商品、测试 SKU、测试活动。
5. 多仓库场景下，当前系统会选择第一条满足库存的仓库记录，发货人员需要结合库存流水确认扣减仓库。
