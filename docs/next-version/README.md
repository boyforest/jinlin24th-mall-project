## 本轮范围

| 负责方 | 交付内容 | 文件范围 |
| --- | --- | --- |
| 前端 | 三角色界面与路由、超管账号管理、咖啡工作台/菜单/订单流水、首页主推与最多六项推荐 | `admin-web/`、首页相关的 `c-uniapp/`、前端测试与验证记录 |
| 后端 | 服务端 RBAC、账号维护、门店授权、咖啡交易及人工接单/制作/退款、流水、提醒服务衔接 | `src/`、`sql/`、必要配置/脚本、后端验证记录、共用契约 |

首页复用现有广告表与接口；后台 RBAC 仍须保护运营接口。首页公共运营首版只保留超管维护，是否开放给商品管理员留待用户确认，不自行扩大授权。

本轮不新增顾客客户端、小程序结算/订单详情页面或订阅授权弹窗，不重做其他小程序页面。后端咖啡交易接口可以实现和测试，但不能因此宣称顾客已经能完成真实下单或订阅提醒。咖啡线上下单开关默认关闭；正式开放前须单独确认小程序交易入口接入并完成真实链路验收。

保留人工接单：付款确认 → 待接单 → 待制作 → 制作中 → 待取餐 → 已取餐。接单和开始制作是两个动作。整单制作、整单取餐、整单全额退款；不自动接单，不擅自设定已付款订单无人处理时的自动退款规则。

不实施：AI 助手、美团/抖音核销、叫号屏、打印、原料库存、排班、部分退款、广告统计、运营审批、自定义角色权限编辑器。

## 两个对话如何并行

- 使用两个独立 Git worktree/检出目录，不能在同一个目录分别切分支。
- 建议前端分支 `uniapp-coffee-workbench-ui`，后端分支 `uniapp-coffee-workbench-backend`；不使用 `codex/` 前缀。
- 先将本目录方案单独提交为共同基线，再从该提交创建实施分支；不得顺带提交现有无关改动、本地密码或配置。
- 前端只维护自己的代码及 `frontend-verification.md`；后端维护自己的代码、`backend-verification.md` 和共用契约。验证记录为实施完成后新增，不必另建流程系统。
- 本包的旧阶段 A 文档仍保留历史意义；本轮新增权限和交易能力按本包契约实施，未变更的目录/购物车/商品接口继续兼容旧契约。
- 接口字段或路径确需变更，由后端先更新共用契约并交接变更，前端随后适配。不能各写一份互不一致的契约。
- 合并、推送、数据库正式迁移、部署和上传小程序由后续验收统一处理；开发对话不以本实施文档作为生产发布授权。

前端可以先完成首页、界面布局和明确标注的测试夹具；后端依次交付账号上下文、账号管理、门店授权、咖啡订单动作与流水。模拟联调和真实服务联调必须分别记录，生产代码不带模拟成功降级。
