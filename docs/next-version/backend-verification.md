## 覆盖的业务

- 三种固定角色的上下文、后台账号分页/创建/重置/启停用/授权、密码哈希和敏感信息不返回。直接访问原商品用户、商品订单及支付、库存仓库、客户跟进、分销、优惠券、共享运营等路由时执行模块授权。
- 真实 MVC 拦截链验证 401/403/404/409、受限 token 只能改密、服务端门店范围、未知字段和字符串 ID、整数版本校验。真实服务登录、首次改密、不同角色落点，以及密码重置后旧 Redis 会话立即 401。
- 门店绑定为空和越界拒绝，首店创建只允许超管；旧未知角色保留，无权限时不默认进入商品后台。并发停用两个超管后仍保留一个启用超管。
- 服务端定价与不可变明细快照、菜单版本冲突、本人订单边界、同用户请求键去重、不同参数冲突、并发取餐号唯一；不清空购物车、不影响商品库存和佣金。
- 独立商户/金额/币种/订单校验；真实 RSA 签名和 AES-GCM 加解密测试验证公钥 ID、签名篡改、过期头、非法密文。重复/乱序支付事实不回退已支付状态。
- WAIT_ACCEPT 人工接单、开始制作、制作完成、取餐完成，版本冲突和重复动作事件唯一；accept/reject 并发只成功一次。
- 拒单及全额退款、稳定退款号、PROCESSING 不误报成功、网络超时后按原退款号查询恢复、退款失败冻结及迟到成功确认；取消关单与渠道付款竞争、失效订单付款后的持久化全额退款。
- 到期未付款取消；已付款无人接单继续保留。跨日工作台、20 条首屏和后续分页、按阶段时间排序、独立收款/退款日期流水及负净额。
- READY 同事务唯一通知任务，缺模板 SKIPPED、SDK 受理 SENT、网络不确定 UNKNOWN、重复调度不盲目重发；提醒结果不影响取餐状态。
- 真实 HTTP 验证新订单/工作台/流水及回调路径已注册；原公开目录、营销读取、商品后台用户查询仍可用。未登录交易请求 401、独立渠道关闭时回调 503，错误没有伪装成空数据或 404。

MySQL 验证发现初始 `next_query_at` 纳秒值会被现有 DATETIME 列四舍五入到未来，导致首次退款查询被跳过。已将咖啡业务时钟及渠道时间统一到现有秒精度，重新通过上述检查。登录使用数据库规范用户名，避免 MySQL 大小写别名导致会话撤销遗漏。

## 前端交接及验收边界

接口路径和展示字段沿用 [共用契约](implementation-contract.md)。补充了工作台续页条件、新接口字段长度/键格式约束和业务码表：进行中状态且无日期的订单列表跨日返回同列未退款订单；普通订单列表仍默认今天。前端须使用服务端权限、allowedActions 和 expectedVersion，409 后重新读取。

`COFFEE_ORDERING_ENABLED` 默认仍为 false。测试未连接真实商户，未产生真实付款/退款或真实顾客订阅消息；生产数据库和部署未操作。真实商户联调、顾客端下单支付入口、订阅授权及微信开发者工具/真机验收仍属后续验收条件，不能据本记录宣布全部闭环通过。部署与恢复操作见 [部署文档](backend-deployment.md)。
