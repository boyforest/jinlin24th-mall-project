## 1. 必须调用 stop-that-shit

开始时调用 `$stop-that-shit change -- 按本文件与共用契约完成前端实施`，并读取 [SKILL.md](/Users/boyforest/.codex/skills/stop-that-shit/SKILL.md)。复用现有 React/Ant Design、uni-app/Vue 和请求工具，不换框架，不新建一个前端仓库。

只补需求缺口；不为减少文件数把不相关功能堆进单页，也不为未来扩展引入通用工作流、权限编辑器或广告平台。必要交互和权限验证完成后结束，不反复扩大验证范围。不得因技能自行停工等用户批准常规实现选择。

## 2. 工作区和文件边界

独立工作目录，分支 `uniapp-coffee-workbench-ui`。修改 `admin-web/`、已约定的首页相关 `c-uniapp/` 及前端验证记录；不修改 Java、SQL、支付配置和共用契约。保留用户已有改动。

后台角色、权限、门店 ID 和允许操作以真实接口为准。可用开发/测试夹具并行做 UI，必须与契约一致，不能进入生产或在请求失败时伪装成功。接口变化交给后端更新契约，不另取一套字段名。

## 5. 界面与操作要求

### 5.1 超管账号与权限页

路径 `/system/accounts`。列表显示账号、名称、角色、门店、状态、最近登录；搜索及筛选按契约请求服务端。创建表单使用真实角色/门店选项；咖啡角色必须绑定门店，没有门店时提示先由超管建立首店，不默认写 ID=1。

分配固定角色并显示权限说明，不增加权限勾选编辑器。重置密码用临时密码输入，不展示原密码；不提供删除账号。停用、降级或重置要明确说明影响；后端拒绝最后一个超管变更时就地提示，不能假装成功。

本账号被撤销会话时按401退出；普通角色访问账号页面显示无权限，不能先渲染列表再隐藏。表单关闭后清理密码输入，不能把临时密码存到 localStorage、日志或截图中。

### 5.2 咖啡工作台

宽屏四列待接单、待制作、制作中、待取餐；平板/窄屏切页签，三个主导航入口不变。大号取餐号，直接读到完整饮品规格、杯数、备注和等待时间。统一订单卡片宽度，整单处理。

确认接单 → 开始制作 → 制作完成 → 确认取走，按契约 allowedActions 显示。接单和开始制作两个动作均保留。拒单/退款输入原因并核对全额金额；确认取走增加简短核对。提交期间按钮提供反馈，失败保留订单，409刷新最新状态。

建议每5秒在可见页面刷新，前一轮结束后再排下一轮；切出页面或退出时清理轮询。分页显示剩余数量、允许继续读取，不能默默只显示前20单。保留已有卡片位置、展开状态，避免整页闪动；数据变化后以服务器排序为准。

连接失败显示最后成功更新时间，保留旧内容并标为可能过期；首次加载失败提供重试。新单视觉提醒配可选声音，首次主动开启声音；初次全量加载与重连存量数据不集体鸣响，不默认浏览器一定允许声音。暂不设置未确认的自动拒单或超时退款阈值。

### 5.3 菜单、订单与流水

售罄/恢复复用已有 SKU available 和保存接口，不增加库存数量系统。门店暂停仍保留待处理订单，不把暂停当清空队列。

订单按日期、号码、状态查询，详情展示真实操作记录及提醒结果；退款仅整单全额，无金额编辑器。收款、退款、净收款与订单数按后端口径展示，净收款允许负数，明确不等于银行卡到账或利润。

### 5.4 首页运营最小改造

读取现有 home_banner 有效列表第一条；读取 home_recommend 前六条。推荐每行两个，零条隐藏、单数末项靠左，不固定凑满六个。沿用现有图片处理、标题和副标题，不展示手工价格，不做下架自动联动。

主推与推荐请求各自处理失败，不因其中一项异常清空全部运营内容；始终保留业务入口。保留公告/弹窗配置和原有行为。复用 product/category/page 跳转，页面类型需按现有路由正确使用 navigateTo 或 switchTab，不重写通用导航系统。

## 6. 顺序与协作

1. 先做首页最小改造和后台权限上下文骨架。
2. 对齐账号接口，完成三角色登录落点与超管账号页。
3. 搭咖啡布局、复用菜单维护，按契约做工作台和订单流水。
4. 后端接口到位后换成真实联调，修正状态/权限/失败处理。

后端交易API实现不意味着可新增小程序咖啡结算页、订单详情页、适老化界面或订阅授权弹窗。本轮不修改现有咖啡“暂未开放”的交易入口，不自行开启 placeOrder/payOnline；发现交易展示需要新契约时记录为后续接入事项。
